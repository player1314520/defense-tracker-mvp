# V9-P4：本地智能体编队与证据约束情景推演

更新日期：2026-07-25

## 已实现

### 07 智能体编队

- 四类模板：快速研判、专题深挖、情景推演、要讯成稿。
- 任务以组织级密文 `job` 记录持久化，状态覆盖
  `queued`、`running`、`waiting_user`、`succeeded`、`failed`、`cancelled`。
- 搜集、精读、构架、成稿、校验五阶段独立保存进度与阶段输出。
- 大纲完成后进入 `outline` 人工闸门；校验完成后进入 `release` 人工闸门。
- 失败记录明确区分来源不可用、网络错误、AI 超时、AI 拒绝、校验错误、
  存储错误和进程中断；失败任务从原阶段恢复，不丢弃既有阶段输出。
- “AI 执行本阶段”只调用当前已解锁桌面的本地 API；证据在内存解密，
  调用用户本机配置的 AI 端点后，输出立即加密写回。Railway 与飞书没有执行入口。
- 同时保留“保存人工输出并推进”，允许人在本机完成某阶段后继续同一状态机。

### 08 情景推演

- 每个推演强制包含有效基础证据，并固定标记为 `scenario_inference`。
- 基准、升级、缓和三分支并列保存摘要、触发器、观察指标、反证和置信度。
- 红队、蓝队、裁判输出分别保存；非空输出必须引用有效证据。
- 服务层拒绝未知分支、未知角色、无证据输出、非有限置信度和跨类型引用。
- 桌面和手机界面持续显示“推演/推断，不得作为已验证事实引用”。

## 数据与安全边界

- `job`、`scenario`、阶段输出、团队输出和错误详情只以 AES-GCM 密文进入数据库与 outbox。
- V9 任务执行 API 仍受 loopback 限制；没有新增 Railway、飞书或云端明文执行器。
- 浏览器验收使用独立 `build/p4-ui-runtime`，完成后已移入 Windows 回收站，
  可恢复；正式用户数据未被修改。

## 诚实边界

1. 当前 AI 阶段执行是同步本地请求；模型响应期间该 HTTP 请求会占用一个工作线程，
   后续 P7 仍需迁移到可取消的本地后台执行器。
2. “本地执行”表示编排、解密和凭据只在桌面发生；若用户配置的是互联网 AI 端点，
   被选中的证据会按用户配置发送给该端点，它不等于离线模型。
3. 任务状态机能在失败后恢复，但操作系统强制终止发生在外部请求过程中时，
   重启后需人工“标记中断”再恢复，尚未自动判定僵尸任务。
4. 情景分支置信度是分析人员或模型的工作判断，不是统计概率，也不要求三者之和为 100%。
5. 自动输出不能证明军事事实；未经证据核验和人工闸门，不得进入正式签发。
