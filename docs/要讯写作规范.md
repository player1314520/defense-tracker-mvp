> 本规范基于飞书机器人 `_generate_brief_docx()` 权威模板，整合历次实战校正要求。
> 调取此规范的标准激活语见文末。

## 二、内容硬性红线（违反任一条重写）

1. **六部分结构完整** —— 事件时间/价值点/标题/正文/信息来源/报送人电话行，不得增减
2. **事件时间具体可核** —— 写原文明确记载的具体事件日期，并与对应来源一致；禁用“近期”“近日”“日前”，不得用发文日期冒充事件日期
3. **价值点独立提炼** —— 必须说明标题之外的战略含义、风险变化或对我影响，不得复制标题或仅换序复述
4. **正文帽段完整** —— 先用约80-120字简述基本情况，在既定DOCX版式中约占3-4行，再展开主体分析
5. **层意标点统一** —— 使用（1）（2）（3）编号时各层以句号结束；不编号时各层一般用分号分隔，最后一层用句号收束
6. **正文字数250-350字** —— 帽段计入总字数，超则裁剪
7. **标题长度适中** —— 标题必须为8-15字，禁用中文逗号“，”和英文逗号“,”
8. **标题警示词收尾** —— 必须以“值得关注”或“值得警惕”四字结尾（不得用“威胁/压力”作结）
9. **禁用markdown符号** —— #、*、-、**、_ 等
10. **PLA机关军语文风** —— 必须出现“研判/建议/着力/加强/威胁/值得警惕”等词，不得口语化
11. **不得编造数据** —— 数字、名称、日期须源自素材
12. **建议范式固定** ——“建议持续跟踪X的要素一、要素二、要素三，针对性加强能力一、能力二、能力三能力建设”
13. **报送人行留空** ——“报送人：           电话：”（报送人后留11个空格，电话后留空）
14. **报道署名闭环** —— 帽段“据XX报道，”中的XX必须与信息来源首条名称一致，XX后不加发文日期
15. **公众号转引追源** —— 公众号引用外网消息时优先查找外网第一信源；找不到时写“据XX公众号报道，”，且该短语中不加日期
16. **来源逐条写全** —— 所有实际引用来源均按“XX M月D日发文《标题》”列明，多条用中文分号“；”分隔
17. **媒体名与标题中译** —— “据XX报道”中XX禁用英文域名或英文媒体名，信息来源行《》内英文标题必须准确译为中文

## 三、标题额外要求（实战补丁 · 最新版）

### 3.1 硬性规则

| 规则 | 说明 |
|------|------|
| **字数范围** | **8-15字**（少于8字或超过15字均须重写） |
| **单行显示** | 方正小标宋简体 22pt 字号下，8-15字应在一行内完整显示 |
| **三元素结构** | 主体 + 核心动作 + 警示结尾，无第四元素 |
| **警示词收尾** | 必须以"值得关注"或"值得警惕"四字结尾 |
| **禁用逗号** | 不得出现中文逗号“，”或英文逗号“,” |
| **统一整齐** | 五篇要讯标题均须落在8-15字范围内，并尽量齐整 |

### 3.2 精简禁用词表（出现即删）

| 禁用类别 | 冗余词汇示例 | 处理方式 |
|----------|--------------|----------|
| **头衔冗余** | 总统/防卫相/参议员/国务卿 | 直接用人名，如"马科斯" |
| **动作修饰** | 率团/国事/正式/专项 | 删，保留动词本身 |
| **规模描述** | 加速/全面/深度/体系化 | 能删则删 |
| **具体细节** | 216架/5人/052D/AH-64D | 移入正文/价值点 |
| **目的补语** | 为XX铺路/威胁/压力（非结尾时） | 用简短动宾代替 |
| **机构冠词** | 五角大楼→美军、国产→本国 | 用更短同义词 |
| **"国产/自主/本土"** | 国产无人机工业体系 | "无人机产业" |
| **复合名词** | 工业体系/战略储备/武器储备 | "产业""武器库" |

### 3.3 标题对照示例（三轮迭代）

| ❌ 过长原版 | ⚠️ 中间版 | ✅ 最终精简版（15字） |

| 五角大楼复制乌式无人机袭击演训值得关注（19字） | — | **美军复刻乌军无人机战法值得关注** |
| 菲总统马科斯国事访日菲日同盟升级值得警惕（20字） | — | **马科斯访日菲日同盟升级值得警惕** |

### 3.4 精简操作路径

```
原始标题 → Step1：删头衔（总统/防卫相→人名）
        → Step2：删量词（具体数字/型号移入正文）
        → Step3：删修饰（加速/全面等形容词）
        → Step4：合并动词（"率团访华"→"访华"）
        → Step5：压缩复合名词（"工业体系"→"产业"）
        → Step6：核对字数为8-15字、无中英文逗号，末尾是"值得关注/值得警惕"
```

## 五、正文范式模板

**事件时间模板：**
```text
事件时间：2026年8月12日
```

事件时间填写原文能够支持的事件发生日期，不得写“近期”等模糊时间。原文未载明具体事件日期时，应退回补证，不得直接以媒体发文日期替代。

**编号式正文模板：**
```
据【与信息来源首条一致的中文名称】报道，【用约80-120字简述事件时间、主体、动作、对象和结果，版式约占3-4行】。
（1）【影响一：战略/政治/军事层面研判】。
（2）【影响二：对我方具体影响】。
（3）【影响三：趋势/后果/连锁反应】。
建议持续跟踪【要素一、要素二、要素三】，针对性加强【能力一、能力二、能力三】能力建设。
```

编号式正文中，每个编号层意必须以句号结束，不得在（1）（2）后使用分号。若不采用编号，则按“【层意一】；【层意二】；【层意三】。”组织，各层一般用分号分隔。

**公众号回退模板：**
```text
据【公众号名称】公众号报道，【约80-120字基本情况】。
```

仅当公众号转引的外网第一信源无法找到时使用该模板；“据XX公众号报道，”中不加发文日期，也不得把公众号转述写成外媒直接报道。

**价值点模板：**
```
【标题未表达的战略含义、风险变化或对我影响】值得关注/值得警惕。
```

价值点不得复制标题，也不得仅通过调换语序或添加程度副词改写标题。

**信息来源模板：**
```
（信息来源：【中文媒体名】M月D日发文《【中文译标题】》；【第二来源中文名】M月D日发文《【中文译标题】》）
```

逐条写全正文实际引用的来源；只有一条时删除第二条及中文分号。第一条来源名称必须与帽段“据XX报道”中的XX完全一致。

## 六、信源选择标准

### 来源追溯与署名

1. **优先第一信源**：先打开并核对原始报道、机构公告或原始文件，再提取事件日期、发文日期、发布主体和标题。
2. **公众号转引处理**：公众号引用外网消息时，优先找到并引用外网第一信源；找不到时保留公众号证据层级，写“据XX公众号报道，”。
3. **报道名称一致**：帽段使用“据XX报道，”，其中XX与信息来源首条名称完全一致，且XX后不写发文日期。
4. **引用来源列全**：正文实际采用几条来源，就在信息来源行列出几条；不得漏列交叉核验中被用于补充事实的来源。
5. **发文日期单列**：只在信息来源行按“XX M月D日发文《标题》”标注媒体发文日期，不把它混入“据XX报道”短语，也不与事件时间混淆。

### 顶级信源（优先选用）
- **美方权威**：USNI News、Defense One、Breaking Defense、Reuters、Bloomberg、CSIS、RAND、Hudson、War on the Rocks
- **日韩**：日本经济新闻、日本时报、共同社、韩联社
- **澳洲智库**：ASPI 战略政策研究所
- **华语权威**：新加坡联合早报、台湾中央社、香港南华早报
- **欧洲**：金融时报、比利时陆军防务网、航空周刊

### 题材筛选优先级
1. **PLA 及周边军事动态**（航母、驱逐舰、岛链、军工、演训）
2. **日美同盟异动**（部署、军工、武器出口政策）
3. **中东/俄乌海上博弈**（封锁、航道、能源安全）
4. **对华战略污名化**（智库报告、技术制裁舆论）
5. **美军转型升级**（新装备、训练体系、作战概念）

### 五篇题材分布建议
- 每日五篇应覆盖**至少3个不同战略方向**
- 避免同质化堆叠
- 优先选择**本日高星级**（7★及以上）信源

## 七、DOCX 生成 Python 骨架

```python
# -*- coding: utf-8 -*-
from docx import Document as DocxDocument
from docx.shared import Pt, Emu
from docx.enum.text import WD_ALIGN_PARAGRAPH, WD_LINE_SPACING
from docx.oxml.ns import qn

def _set_font(run, font_name, size_pt=16, bold=True):
    run.font.name = font_name
    run.font.size = Pt(size_pt)
    run.font.bold = bold
    rPr = run._element.get_or_add_rPr()
    rFonts = rPr.get_or_add_rFonts()
    rFonts.set(qn('w:eastAsia'), font_name)

def _add_para(doc, align=None, left_indent=None, first_indent=None):
    p = doc.add_paragraph()
    pf = p.paragraph_format
    pf.line_spacing_rule = WD_LINE_SPACING.EXACTLY
    pf.line_spacing = Emu(363220)
    pf.space_before = Pt(0)
    pf.space_after = Pt(0)
    if align is not None: p.alignment = align
    if left_indent is not None: pf.left_indent = Emu(left_indent)
    if first_indent is not None: pf.first_line_indent = Emu(first_indent)
    return p

def make_yaoxun_docx(event_time, value_point, title, body, source, out_path):
    doc = DocxDocument()
    sec = doc.sections[0]
    sec.page_width, sec.page_height = Emu(7560310), Emu(10692130)
    sec.top_margin = sec.bottom_margin = Emu(914400)
    sec.left_margin = sec.right_margin = Emu(1143000)

    p = _add_para(doc)
    _set_font(p.add_run('事件时间：'), '黑体')
    _set_font(p.add_run(event_time), '楷体_GB2312')

    p = _add_para(doc, left_indent=1019810, first_indent=-1019810)
    _set_font(p.add_run('价值点：'), '黑体')
    _set_font(p.add_run(value_point), '楷体_GB2312')

    _add_para(doc, align=WD_ALIGN_PARAGRAPH.CENTER,
              left_indent=1606550, first_indent=-1612900)

    p = _add_para(doc, align=WD_ALIGN_PARAGRAPH.CENTER,
                  left_indent=1606550, first_indent=-1612900)
    _set_font(p.add_run(title), '方正小标宋简体', 22)

    p = _add_para(doc, align=WD_ALIGN_PARAGRAPH.CENTER,
                  left_indent=1606550, first_indent=-1612900)
    _set_font(p.add_run('      '), '方正小标宋简体', 22)

    p = _add_para(doc, first_indent=408305)
    _set_font(p.add_run(body), '仿宋_GB2312')

    p = _add_para(doc, first_indent=408305)
    _set_font(p.add_run(source), '楷体_GB2312')

    p = _add_para(doc, align=WD_ALIGN_PARAGRAPH.CENTER)
    _set_font(p.add_run('报送人：           电话：'), '楷体_GB2312')

    doc.save(out_path)
```

## 八、生产流程（标准作业）

1. **启动追踪系统** —— `py <项目目录>/app.py`
2. **轮询待 `/api/status` 返回 online** —— 通常需60-120秒加载RSS
3. **API 拉取今日新闻** —— `curl -H "X-Access-Token: <ACCESS_TOKEN>" http://127.0.0.1:5000/api/news`
4. **筛选当日7★+顶级信源文章** —— 按 `priority.stars` 倒排、Date 过滤，并区分发文日期与事件日期
5. **跨题材挑选5篇** —— 覆盖 PLA/日美/中东/智库/美军5个方向
6. **定位并核对第一信源** —— WebSearch仅用于寻找原文；公众号转引外网消息时优先追到外网第一信源，不能用搜索摘要代替原文
7. **按范式撰写五篇 DOCX** —— 调用 `make_yaoxun_docx()` 批量生成
8. **事件与价值点审核** —— 事件时间必须具体且与原文对应，价值点不得复制标题
9. **帽段与字数审核** —— 帽段约80-120字、版式约3-4行；`len(body)` 必须在250-350之间，超则裁剪重跑
10. **标题审核** —— 标题必须为**8-15字**且不含中英文逗号，末尾必须为“值得关注/值得警惕”
11. **层意标点审核** —— 编号式各层用句号；无编号式各层一般用分号，最后一层用句号
12. **来源闭环审核** —— “据XX报道”与信息来源首条同名；所有引用来源均按“XX M月D日发文《标题》”列全，多条用中文分号
13. **保存至** —— `<桌面>\今日新闻\`

### 文件命名规范
```
要讯_【主体动作精简描述】_YYYYMMDD.docx
```
示例：`要讯_解放军舰艇过航奄美大岛反制日方挑衅_20260422.docx`

## 九、认证与环境

- **访问令牌**：启动日志输出的 `ACCESS_TOKEN`（存于 `.access_token`，不得写入文档或提交）
- **Python 环境**：必须使用 `py` 启动器（feedparser 安装在此）
- **字符编码**：Python 脚本顶部须有 `# -*- coding: utf-8 -*-`
- **stdout 编码**：脚本开头 `sys.stdout.reconfigure(encoding='utf-8')`
- **GFW 规避**：外媒直接抓取失败时，用 WebSearch 定位原文或替代可核验页面；搜索摘要只能作为检索线索，不能作为信息来源

## 十、诚实边界

1. 本规范和文本校验只能检查日期、结构、标点及引用闭环，不能替代打开原文核实事件日期和事实。
2. 无法访问公众号所引外网原文时，不能把转述包装成第一信源；只能按公众号署名并降低证据等级。
3. “帽段3-4行”受页面、字体和排版影响，80-120字只是文本代理；交付DOCX前仍须实际渲染复核。
4. 来源行格式完整不等于报道内容真实；重要事实仍须执行原文页与独立材料交叉核验。
5. Web端导出使用服务器签名的原始素材证据，能阻止浏览器在生成后篡改日期或摘要，但不能证明用户首次导入的材料本身真实；服务重启后旧签名安全失效，须从原始材料重新生成。
6. V9通用版本化稿件不承担要讯签发或导出；所有要讯必须进入写作室中的专用生成、来源校验和DOCX门禁，避免两套规则漂移。
