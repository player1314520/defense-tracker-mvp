# V9-P5 写作、版面与签发

更新日期：2026-07-25

## 本地实现

- 09 写作室把报告与要讯统一为密文 `document` 项目；每段独立保存正文、
  证据 ID、来源状态、事实核查状态和核查备注。
- 稿件支持大纲、草稿、复核、定稿四阶段和完整修订快照；每次修改使用
  单调版本号，过期写入进入既有冲突机制。
- 签发校验不信任客户端或数据库中缓存的 `validation.ready`，每次送审和
  签发都根据真实段落重新计算；无证据或事实核查未通过时 fail-closed。
- DOCX/PDF 导出附来源索引、证据记录 ID、来源哈希、归档时间和链接；
  PDF 内容在进入 ReportLab 富文本解析前执行转义。
- 10 版面计划使用待补证、编辑中、待签发、已签发四列真实密文看板；
  撤回记录和发布审计单独保留。
- Editor 可编辑稿件和编排版面但不能签发；Approver 可签发/撤回但不能
  修改稿件。通用记录 API 不能伪造或覆盖 `publication_item`/`audit_event`。
- 签发把正文、来源索引、稿件版本、正文 SHA-256、签发时间和签发人固化
  为密文不可变快照。撤回只改变发布状态，不删除或改写原签发快照。
- `/api/v9/documents*`、`/api/v9/publications*` 和
  `/api/v9/audit-events` 已新增；旧 `/api/brief`、`/api/agent` 等接口保留。

## 诚实边界

1. 签发校验能保证“每段有引用且状态为已核查”，不能自动证明来源真实、
   独立或足以支撑军事判断，Approver 仍必须人工复核。
2. 不可变快照可以发现和阻止系统内覆盖，但不能阻止已获本机账户权限的人
   截屏、复制或在系统外保存历史明文。
3. 当前 PDF/DOCX 是可追溯交付格式，不是数字签名文件；尚未接入
   Authenticode、可信时间戳或机构电子签章。
4. 浏览器与 EXE 都是本地已解锁客户端；P6 完成前没有真实多设备审批会话，
   也没有在 Supabase/Railway 上运行本阶段正文处理。
5. 本阶段未执行任何远程部署、发布、凭据写入或飞书正文传输。
