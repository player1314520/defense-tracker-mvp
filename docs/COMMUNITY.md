# Community Channels

Use the smallest public channel appropriate for the request:

| Need | Channel | Do not include |
|---|---|---|
| Reproducible software defect | Bug issue form | Secrets, real user data, exploit details |
| Product or architecture proposal | GitHub Discussions | Confidential business or deployment details |
| Lawful public-source suggestion | Data-source issue form | Copied/paywalled text, screenshots, QR codes, personal data |
| Vulnerability | GitHub private vulnerability report | Public proof-of-concept or live credentials |
| Conduct concern | Moderation request with public link only | Private evidence or personal details |

GitHub Discussions is the preferred place for questions and proposals that do
not yet justify a tracked engineering issue. Decisions that affect code or
release gates are summarized in an issue or pull request so they remain
auditable.

The external CLA gate is currently inactive, so external pull requests cannot
be merged. Discussion, bug reproduction with synthetic data, and compliant
public-source links are still useful inputs.

## Honest boundaries

- Public channels do not provide confidentiality.
- The project currently has no guaranteed response time or independent
  moderation panel.
- A discussion consensus does not override licensing, security, privacy, CI,
  or release gates.
