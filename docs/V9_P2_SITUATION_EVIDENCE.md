# V9-P2：真实态势、预警规则与密文证据

更新日期：2026-07-25

## 已实现

### 00 态势总览

- 移除生产界面的 74、66、61、52 演示分数。
- 以来源层级、发布时间衰减、文章优先级和独立来源交叉印证计算信号强度。
- 少于 3 条证据或 2 个独立来源时不生成分数，明确显示“证据不足”。
- 每个区域卡可展开查看公式、证据数量、来源数量、更新时间和来源链接。
- 顶部 WIRE 从当前真实高优先级新闻生成；无数据时显示可解释空状态。

### 01 实时新闻

- 复用既有 RSS 去重、来源健康、翻译、收藏、已读和快速预警词能力。
- 新增客户端密文预警规则：规则名称、关键词、最低星级、严重度、来源限制、
  启停状态和版本均进入 V9 加密记录层。
- 新增过去 24 小时规则命中节奏带；只统计真实新闻与启用规则的匹配结果。
- 新增“归档证据”入口，重复归档按文章 ID 或 URL 哈希幂等处理。

### 02 证据库

- RSS 新闻以独立数据密钥 AES-GCM 加密为 `evidence` 记录。
- 记录保留版本、内容哈希、来源 URL、来源名、发布时间、归档时间、引用状态和批注容器。
- 证据库只在已解锁的本地客户端解密，并在内存中搜索。
- 证据卡支持拖拽，载荷只包含记录 ID，供后续案件、情景和写作屏接入。
- 只打开空证据库不会创建工作区或消耗一次性恢复码；首次实际写入才创建。

## 数据与安全边界

- 云端 schema 只增加 `alert_rule` 密文类型；Admin/Owner 可写，其他角色不能写规则。
- 态势计算和规则匹配只运行在本地进程；没有把新闻正文或解密规则发往 Railway、飞书或第三方服务。
- 浏览器验收创建的临时组织、规则和证据已从活动运行目录移出，未污染用户正式数据；
  两个测试运行时文件已移入 Windows 回收站，仍可恢复。
- 未执行 Supabase migration、Railway 部署、飞书写入或任何远程发布。

## 诚实边界

1. “态势指数”只是公开来源信号强度，不代表战场事实、军事结论或预测概率。
2. 当前证据归档保存 RSS 可获得的标题、摘要和来源链；付费墙或受限页面的完整原文不会被虚构，
   完整原文抓取与文件版本管理仍需后续专用导入流程。
3. 规则节奏只覆盖当前客户端持有的近 24 小时新闻缓存；客户端长期离线时不能代表全球完整事件量。
4. 证据卡拖拽已定义安全记录 ID 载荷，但案件、情景和写作段落的落点会在 P3–P5 接入。
5. 当前本地开发模式仍使用项目兼容数据目录；打包 EXE 使用
   `%LOCALAPPDATA%\DefenseTracker`。开发模式只读程序目录的彻底迁移留在 P7 兼容适配中完成。
